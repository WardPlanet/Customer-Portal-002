# Style guide

The AI follows this guide whenever it writes or rewrites text: imports, pasted text, AI assist and the
per-section suggestions. It is plain text, so edit it and the next AI request uses the change (no restart).

Where this guide says nothing, follow the Microsoft Writing Style Guide. Change that line if the company
standardizes on a different guide (for example Chicago or AP).

## Names and terms

- Write every product, company, system and team name the same way everywhere on the page, spelled the way
  the company officially writes it. Do not put names in quotation marks, and do not change their
  capitalization (no ALL CAPS, no run-together spellings).
- If a source document formats names inconsistently, for example some in quotation marks and some plain,
  write all of them plain.
- Starter list of official names. Check the spelling and add your own: Planet DDS, Denticon, Cloud 9,
  DentalOS, Apteryx, Artemis.
- Use one term for one thing. If the source calls the same thing "ticket", "case" and "request", pick the
  one the company uses and use it throughout.

## Quotation marks

- Use quotation marks only for exact text the reader will see or type, such as an error message.
- Do not use quotation marks for emphasis, names, or "scare quotes".

## Buttons, menus and fields

- Write the name exactly as it appears on screen, with the same capitalization, and no quotation marks.
- In the description and Text blocks, put it in bold: Select **Save**.
- Step text, notes, warnings and headers cannot be bold, so there write the name exactly as shown:
  Select Save.

## Capitalization

- Use sentence case for the page title, headers and step titles: capitalize the first word and proper
  nouns only. Not Title Case.
- Do not use ALL CAPS for emphasis. Use bold sparingly instead.
- Capitalize a job title when it names a role the wiki links to, such as Billing Team Lead.

## Voice and wording

- Write in the active voice and present tense, and speak to the reader as "you".
- Steps start with a verb: "Verify the payment ID", not "Payment ID verification".
- Say only what the reader needs. A step whose title already explains what to do needs no detail text:
  leave it empty rather than restating the title.
- Use short sentences and plain words. Cut filler such as "please", "simply", "just" and "obviously".
- Spell out an abbreviation the first time it appears on the page, with the short form in parentheses,
  unless every reader already knows it.

## Punctuation and numbers

- Use the Oxford (serial) comma.
- Headers, step titles and the page title do not end with a period. Full sentences always do.
- A list item ends with a period only if it is a full sentence.
- Spell out numbers zero to nine in running text and use numerals for 10 and above. Always use numerals
  with units, dates and step numbers.
- Write dates as Month D, YYYY (March 31, 2027) and times as 9:00 AM.
- Avoid exclamation marks.

## Code

- Code, commands and other text in a Code block is copied exactly. None of the rules in this guide
  (capitalization, punctuation, quotation marks, spelling) apply inside it.
- Never edit, "fix" or suggest changes to the contents of a Code block.

## Lists, links and emphasis

- Use a numbered list only when the order matters. Otherwise use bullets.
- Keep list items parallel: all start with a verb, or all are noun phrases.
- Link text says where the link goes ("the refund policy"), never "click here".
- Use bold for button and menu names, and for a key term the first time it is defined. Use italics rarely,
  for document titles. Do not underline anything except links.
